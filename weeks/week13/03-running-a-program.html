13.9   Loading a program by hand

A program in your CPU is bytes in RAM, starting at address 0, with the PC set to 0. Fall 2025’s finished CPU loads a program from a file with a counter and a second RAM; that loader arrives in Week 14. This week you load the bytes yourself, through the test port you have used since Week 10: the 8-bit data pin and its data_e buffer onto the bus.

First problem: the bus is not free. After Simulate → Reset the stepper is on step 1 and clk_e is 1 (Week 11). With fetch wired, that means pc_e is already high, and a PC that has never been written drives EEEEEEEE onto the bus. Raise data_e and you have two drivers. So your CPU tab gets one more input, run, and clk_e and clk_s reach the control unit only through an AND with it. Every enable and every set the control unit produces is ANDed with one of those two, so with run = 0 the control unit drives nothing at all and the bus is yours. Week 14’s END instruction will stop the CPU the same way.

Second problem: nothing sets the PC, the IR, the MAR or the RAM except the control unit. So, like Week 11’s data_s, four set pins of your own, each ORed with the control unit’s line, and one for the RAM’s reset:

LD, ST, DATA and the jumps get their steps 4 to 6 in Week 14. Until then your CPU fetches them and does nothing. That includes the zeros after your program: if you keep clicking, the CPU fetches 00000000 again and again and the PC counts up, which is harmless.

Load every register your program touches

Step 4 copies RB into TMP for every ALU instruction — even NOT, SHR and SHL, which never use TMP. The control table has no exception for them, and adding one would cost gates for no gain. So if your program writes a register you never loaded, step 4 moves EEEEEEEE into TMP and the ALU. This week’s program writes R2, so you load R2 = 0 before running it.

13.11   MOV and SUB are not instructions

The course syllabus says this week’s CPU implements MOV, ADD and SUB. Look at your instruction set from Week 10: ADD is there, and MOV and SUB are not. You have been here before. In Week 7 you learned that MIPS has no blt instruction: the assembler turns blt into slt plus bne, and you wrote that pair by hand. A missing instruction is a sequence of instructions that the machine does have.

MOV uses NOT twice. NOT reads only RA (Week 10), so NOT RA, RB puts the inverse of RA into RB, and NOT RB, RB inverts it back. Two instructions, 48 clicks.

SUB uses a fact from Week 1. In two’s complement, inverting every bit of x gives −x − 1. So:

NOT b = −b − 1
NOT b + a = a − b − 1
NOT (NOT b + a) = −(a − b − 1) − 1 = b − a

Three instructions, and the answer is exact for every pair of bytes, modulo 256, because your carry-in is 0. With R2 = 7 and R1 = 3, SUB R1, R2 runs NOT R2, R2 (R2 = 11111000), ADD R1, R2 (R2 = 11111011), NOT R2, R2 (R2 = 00000100, which is 4).

Two things the sequences do not do
  • SUB needs two different registers. The first NOT changes RB. If RA is RB, it has changed RA too, and the ADD adds the wrong number.
  • The flags are not a subtraction’s. FLAGS captures at step 5 of every ALU instruction, so after SUB they are the last NOT’s. To compare two numbers, use CMP.

13.12   This is a computer

Stop and look at what the Checkpoint 6 program does. Nobody touches the CPU between raising run and reading R2. It reads byte 0 from memory because its PC said 0; it decides what to do from the bits of that byte alone; it moves values between registers through one shared wire, one transfer at a time; it counts its PC on to the next byte and does it again. Every one of those actions is a gate you placed, and every gate is the NAND-built logic of Week 2. There is no other ingredient.

It is also the C tier of your final project, from Week 10: fetch plus every ALU-class instruction, running from RAM. B adds LD, ST and DATA, and A adds the jumps and CLF and runs MYSIM.txt — Week 14.
