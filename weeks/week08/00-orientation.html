Week 8 — Somewhere to Put Things

The RAM matrix, and MIPS memory  |  10/05 – 10/11  |  Estimated time: ~9 hours, including the midterm

Seven weeks about what a machine does with a value. This one is about where it keeps one.

Your hardware can store one byte in a register and transform bytes in an ALU. It has nowhere to keep more than a few, and no way to say which of many it means.

Your software names every operand by register. A C program with int scores[100]; has nowhere to live, and no instruction you know can reach “the location whose number I just computed”.

Both halves need a number that means a place. This week you build the hardware that turns an 8-bit number into one selected byte, and learn the MIPS instructions that compute such a number and use it.

What you build — and what you already own

Two new tabs. Almost everything inside them comes from your file:

  • REGISTER_8BIT ×32 — one inside every byte of RAM. Week 5. Used exactly as it is; do not modify it.
  • DECODER_4TO16 ×2 — one for rows, one for columns. Week 3, which told you it would be used for this.
  • MEM_8BIT ×1 — the Memory Address Register. Week 5.
  • RAM_BYTE New. One register plus four gates and a buffer, so it only answers when its row and column are both selected.
  • RAM_16X16 New. The MAR, both decoders, and 32 bytes — designed for 256, built for 32.

The two tracks

Hardware — Checkpoint 3

The addressable byte; two-dimensional decoding; the MAR; why 32 of 256; a shared output line that, unlike the ALU’s, really is a bus. Verified with a ten-step table.

Assembly — memory

lw, sw, lb, lbu, sb. Base plus offset. Word alignment. Which byte of a word comes first in MARS. Arrays, walked two ways. Strings as arrays of bytes.

The week’s best single fact: the two tracks use the same number

When a MIPS program says lw $t0, 8($s0), the address it computes is exactly the kind of number your RAM takes. Page 3 follows it the whole way:

a[2] → lw $t0, 8($s0) → your ALU’s ADD leg → your MAR → a row and a column → one AND gate

The midterm

The midterm is this week and covers Weeks 1 through 8 — everything from binary through this week’s memory material, on both tracks. Your instructor will post its format and window separately. The fastest review is the self-checks on each week’s pages and the verification tables on each hardware page.

Tools and reading

  • Logisim Classic 2.7.1 — your single course .circ file. Two new tabs; nothing from the Plexers, Arithmetic or Memory folders.
  • MARS — the Data Segment pane in the Execute tab is this week’s most useful view.
  • Saylor CS301 — log in at the CS301 course page and open Unit 2: Instructions — Hardware Language for load/store and arrays, and Unit 6: The Memory Hierarchy for how memory is organised. Neither covers building RAM from your own decoders; pages 1 and 2 are the source for that.
