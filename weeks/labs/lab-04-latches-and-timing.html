Why This Lab Exists

What we have: Circuits that compute. An adder that adds two bytes, decoders that turn a code into a one-of-N selection. Every one of them is combinational: its output depends on what its inputs are right now, and on nothing else.

What we can't do yet: Keep anything. Change the inputs and the previous answer is not stored somewhere inconvenient — it is gone. That rules out more than it sounds like. You cannot add three numbers, because there is nowhere to put the first sum. You cannot count. You cannot do one thing and then another, because "and then" requires remembering that the first thing happened.

What we can do after today: Hold one bit, in a circuit made of two NAND gates wired back into each other — and then control when that bit is allowed to change. The second of those circuits, MEM_1BIT, is the memory cell your CPU is actually made of. Every register, the program counter, the MAR, the IR and every byte of RAM you build for the rest of this course is made of the circuit you finish today.

This is the pivot point of the course, and it is worth saying plainly why. Everything you have built so far is a shape that transforms whatever is presented to it. After today, a circuit can have a past. That is the difference between a calculator and a computer, and it costs two gates.

One Thing You Are Not Building Today

This week's reading teaches the clock and the edge-triggered D flip-flop, and you will be asked to reason about a flip-flop on Assignment 4 and on Quiz 1. You do not build one — not in this lab, and not on the assignment.

That is deliberate, and it is not a shortcut. Your CPU's datapath does not contain a flip-flop: its registers are level-sensitive MEM_1BIT cells written by a Set line. The machine's one edge-triggered element lives in the clock, and you meet it in Week 11 with the circuit that uses it. Since Week 3 this course has trained you that every circuit you build reappears later — so when one doesn't get built, you should hear the reason rather than notice the gap.

What You Will Be Able to Do

By the end of this session you will be able to:

  1. Build an S-R latch from two cross-coupled NAND gates, and demonstrate that it holds a value after you release the input.
  2. Explain where the stored bit is — and account for the fact that the same inputs support two different stable outputs.
  3. Reach the forbidden state deliberately, describe why releasing it has no defined outcome, and name that as a race condition.
  4. Build MEM_1BIT, the course's four-NAND memory cell, with pins In, Set and Q, and edit its circuit appearance so eight of them are readable side by side next week.
  5. Store a value on purpose using the three-step procedure you will use for the rest of the course: set In, raise Set, drop Set.
  6. Draw an output waveform by hand for a level-sensitive cell and for an edge-triggered flip-flop, given the same input, and get the difference right.

Part 2 — SR_LATCH: Two Gates That Remember ~20 minTogether

Two NAND gates. That is the entire circuit — there is no third component and nothing in it that stores anything. The storage is the loop.

Before you place anything, one convention that causes more wrong builds this week than everything else combined. A NAND-built S-R latch has active-LOW inputs: they act when you drive them to 0. The course writes that into the pin name — a name beginning with a lowercase n is active LOW. So nS is "not-S": drive it to 0 to set. Read that sentence twice; it is the thing people get backwards.

  1. Open the SR_LATCH tab. Place two NAND gates, one above the other.
  2. Add input pins nS and nR. Set both to 2-state with pull-down behaviour.
  3. Wire nS to one input of the upper gate; wire nR to one input of the lower gate.
  4. Cross-couple them. The upper gate's output goes to the lower gate's free input, and the lower gate's output goes to the upper gate's free input. Each gate's output is the other gate's input.
  5. Add output pins q (from the upper gate) and nq (from the lower gate).
Expect a Mess When the Simulation Starts

With pull-down pins, both inputs come up at 0 — which for this circuit is the forbidden state, and it settles unpredictably. You will likely see flickering, or a red error state on a wire, before anything stabilizes. That is not a wiring fault and not a Logisim bug. A real latch has no defined state at power-on; the simulator is being honest that nothing has determined the answer yet. Poke nS or nR to 1 and it will settle. Part 3 is about exactly this.

Now the test that actually matters

The rows above do not prove this circuit is memory. Three of them could describe an ordinary combinational circuit. Do this instead, slowly, and watch it:

  1. Drive nS to 0. q goes to 1.
  2. Return nS to 1 — let go of it entirely. Both inputs are now 1 and nothing is driving the circuit.
  3. q is still 1.
  4. Now reset it: drive nR to 0, then return it to 1. q is still 0.

Both inputs are at 1 in step 3 and in step 4, and the output is different. The present inputs do not determine the present output. That is memory, and it is the only row of the table whose value cannot be written down without knowing what happened earlier.

Sit with this one for a moment rather than moving straight on — and if you want the mechanism rather than the demonstration, trace it. With nS = nR = 1, suppose q = 1. Then the lower gate sees 1 and 1, so it outputs 0; the upper gate sees a 0, so it outputs 1 — which is where we started. It is self-consistent. Now suppose q = 0 instead, and trace it again: that is self-consistent too. Two stable configurations, identical inputs. The stored bit is nothing more than which of the two the loop settled into, and which one it is was decided earlier.

Why NAND, Specifically

Week 2 proved NAND is universal: it can build any logic function. This circuit is the reason that claim is more interesting than it sounded. A latch is not a logic function at all — its output is not determined by its inputs. Two NAND gates build it anyway. Universality did not predict this, and no truth table describes it.

It is also not a toy construction. The NAND-based S-R latch is the circuit real SRAM cells use.

One Circuit That Does Not Come Back

Since Week 3 every circuit you have built has been a component of a later one. SR_LATCH is the exception, and you should hear it said rather than work it out: nothing later in this course contains it. MEM_1BIT is a more economical four-gate construction, not a wrapper around this tab.

You build it anyway, and you keep it as its own tab, because it is where memory-as-feedback is learned and because Part 3's argument needs a circuit that can reach the bad state. It is also worth 10 points on Assignment 4.

Part 3 — The Forbidden State, on Purpose ~10 minTogether

Drive both nS and nR to 0. Both outputs go to 1. q and nq are both high, which contradicts the one thing their names promise: that one is the complement of the other.

That is odd but it is not the real problem. The state is reachable, it is stable while you hold it, and it is merely useless. The real problem is leaving it.

2
Release both inputs at the same time, several times over

From the forbidden state, return nS and nR to 1 together. Both gates now try to drive the loop at once, and which one wins depends on which gate is physically faster.

Do it repeatedly. Watch what Logisim does — oscillation, an error state on the wire, or a value that is not the same one you got last time. Compare with the person next to you. If your answers differ, neither of you is wrong; that is the finding.

This Is a Race Condition — the First One in This Course

The outcome is decided by which of two physical components happens to be faster, and that is not a thing your design controls or your simulator can know. In a real circuit, two runs of the same design can land differently.

Then the engineering lesson, which is the reason this is a whole part of the lab rather than a footnote: you do not fix a race by being careful. A rule that says "never drive both inputs low" is a rule enforced by a circuit that cannot read it. The fix is to build a circuit in which the bad state is unreachable — which is exactly what you do in Part 4.

Two more things follow from this, and they are worth having in your notes because the first one costs students an hour every year:

  • The flicker at startup is the same phenomenon. When the simulation begins, both pull-down inputs are at 0 and both gates race. The circuit lands in a stable but arbitrary state. Nothing has determined the answer, and Logisim showing you that is the simulator being honest rather than broken.
  • This is why real sequential systems carry a global reset — a signal that forces every memory element into a known state at power-on, so the machine starts from somewhere defined rather than from whatever the gates decided.
The Asynchronous Exception, Stated Once

This raw latch is asynchronous: it responds the moment an input changes, with no clock involved anywhere. That is not an oversight in the design, it is the point — memory has to exist before it can be scheduled, and seeing the unscheduled version first is what makes control look like a solution instead of a convention.

From here on, this course is different. Every storage element you build from Week 5 forward changes only when something tells it to, and the clock is what does the telling. SR_LATCH is the one deliberate exception, and this part is why.

Part 4 — MEM_1BIT: The Cell Your CPU Is Made Of ~22 minTogether

Two problems are left over from Part 3. The forbidden state is reachable, and the latch changes the instant an input moves — there is nothing that can say not yet. One circuit fixes both, and it does it by construction rather than by discipline.

The idea: instead of two inputs that say "set" and "reset," have one data input and one permission input. Put a NAND in front taking In and Set. Now notice something worth pausing on — when Set is 1, that gate's output is already In inverted. So a second NAND fed by that output and Set gives you the other polarity for free. Four gates, not five. There is no separate inverter, because the first gating gate is already doing that job.

  1. Open the MEM_1BIT tab. Place four NAND gates — two will be cross-coupled as the latch, two sit in front as the gating.
  2. Add input pins In and Set (2-state, pull-down) and one output pin Q.
  3. Gate A: inputs In and Set.
  4. Gate B: inputs are gate A's output and Set. Again: there is no NOT gate here.
  5. Cross-couple the remaining two gates exactly as you did in SR_LATCH, and drive them from gate A and gate B — A into the set side, B into the reset side.
  6. Bring only Q out to a pin. Do not add a Q' pin.
Two Names, and a Missing Pin

Textbooks call this circuit a gated D latch — one data input, one enable, output takes the data while enabled. This course calls it MEM_1BIT because that is what it is to your machine and what Week 5 instantiates. Both names describe the same circuit; you will meet the textbook one in outside reading.

And the missing Q' is deliberate. SR_LATCH keeps its complement because there the complement is the lesson. Here nothing reads it, and a pin nothing reads is a wire to maintain and a thing to mis-connect. Interfaces get smaller as designs settle.

Why the pull-down setting means something different here. Same pin setting as SR_LATCH, opposite effect. These inputs are active-HIGH, so coming up at 0 means "not being written," which is harmless — where on the raw latch, coming up at 0 was the forbidden state. A pull-down is just a pin coming up at 0; whether 0 is safe depends entirely on what the pin means.

Verify — transparency, then hold
  1. Set Set = 1 and poke In back and forth. Q follows it immediately. The cell is transparent while Set is high.
  2. Return Set = 0 and poke In again, several times. Q does not move.
  3. Run the three-step store, which is the procedure you will use for the rest of the course:
    — put the value you want on In;
    — raise Set to 1;
    — drop Set back to 0. The value in Q is now fixed until the next time Set goes high.
  4. Satisfy yourself that no combination at all of In and Set drives both internal latch inputs low. Try to find one. The forbidden state needs In and its own inverse to be 0 at the same time, and the wiring makes that impossible.
Both Problems, Solved at Once — and Neither by Being Careful

One input replaced two, so there is no way to ask for set and reset together. And because In and In-inverted can never both be 1, the two latch inputs can never both be 0. The bad state was not avoided. It was designed out.

That is the answer to the question Part 3 left open, and it is a move you will see again: this machine removes hazards by shaping the circuit, not by asking anyone to remember a rule.

Troubleshooting — MEM_1BIT misbehaving
Q never changes, whatever I do
Check gate B. Its inputs are gate A's output and Set — not In and Set. If both front gates take the same two inputs they produce the same value, and the latch is never told anything.
Q follows In even when Set is 0
One of the front gates is probably bypassed — trace the wire from In and make sure it reaches only gate A, not the cross-coupled pair directly.
Red wire somewhere in the loop
Two outputs are driving the same wire. In this circuit that usually means a cross-couple was wired to a gate's output instead of its free input.
It flickers like the raw latch did
If it flickers with Set = 0, the gating is not doing its job — with Set low, both front gates should output 1 and the latch should simply hold. Check that Set reaches both front gates.
I built it with five gates and a NOT, and it works
It does work, and it is not wrong — it behaves identically. It earns partial credit rather than full on Assignment 4, because the four-gate version is the one Week 5 expects. If you have time in the room, rebuild it as four; if you do not, keep the working one and rebuild it later.

Part 5 — Draw It in Time ~20 minTogether, then your own

This is the segment that pays off furthest. Assignment 4 Part B asks you to draw output waveforms, Quiz 1 asks you to reason about the difference between two devices, and every debugging session for the rest of the course is a question about what happened when. It is a skill, and skills are practised rather than read.

A timing diagram is simpler than it looks. Time runs left to right. Each row is one signal. A vertical edge is a transition. The high level means 1, the low level means 0, and that is the whole notation.

Below is an input pattern, sixteen moments long. Print this page, or copy the figure onto paper, and fill in the two blank rows by hand. Do not use the widget yet — drawing it first is the exercise, and checking it afterwards is only useful if you committed to an answer.

The In row drives both devices. MEM_1BIT is controlled by Set; the flip-flop is controlled by CLK, whose four rising edges are marked. Both output rows start at 0.
4
Draw MEM_1BIT's Q

Work left to right, one moment at a time, and ask the same two questions at each: is Set high? If yes, Q is whatever In is. If no, Q is whatever it already was.

Mark every point where Q changes, and be ready to say what caused it. Two moments in this pattern are worth watching for: one where In changes during a Set window, and several where In moves while Set is low and Q should not budge.

5
Draw the flip-flop's Q

Different rule, and only one: at a rising edge of CLK, Q takes whatever In is at that instant. Everywhere else, Q does not move at all. The four rising edges are marked with green guides so you can read the correspondence down the page rather than take it on trust.

The interesting thing is what happens between edges. Follow In across moments 4, 5 and 6 and ask what the flip-flop does about any of it.

6
Verify against your own circuit

Before you check with the widget, check against hardware. In Logisim, poke your MEM_1BIT through the first six moments of the pattern by hand — set In, set Set, read Q, write it down, move to the next moment. Six steps is enough to know whether your drawing and your circuit agree.

If they disagree, one of them is wrong and finding out which is the whole exercise. An answer key would tell you that you missed; a circuit shows you what is actually true and lets you find your own error.

What the Two Rows Should Have Shown You

MEM_1BIT's output moves whenever Set is high and In changes — it is a window, and anything that happens inside the window gets through. The flip-flop's output moves only at four instants in the whole pattern, and an input that changes and changes back between two edges is never seen at all. That is what sampling means, and it is the difference the two rules produce.

Your CPU relies on the first behaviour. Its registers are transparent while Set is high, and the control signals are shaped so that the data on the bus is stable for the whole window and a moment either side — the same move you saw in Part 4, one level up: the hazard is removed by the design, not by care. That is Week 11's material, and this is the picture it will refer back to.

Part 6 — Quiz 1 Concept Sweep ~10 minTogether

Quiz 1 covers Weeks 1 through 4 — the whole of Phase 1 — and it is open all week, one attempt, 60 minutes, open notes. The last ten minutes of this session are a verbal walk back down the ladder we have climbed. Nothing is written down; the point is to notice which rung you cannot explain.

We go down it in this order, out loud:

  1. A memory cell holds one bit, and changes only when Set says it may.
  2. It is four NAND gates — two that gate, two that latch — and the forbidden state is impossible in it by construction.
  3. The latch is two NAND gates whose outputs feed each other. Two stable states under identical inputs; the bit is which one it settled into.
  4. A NAND gate is one of the gates you built in Week 2, and NAND alone can build every logic function — and, as of today, one thing that is not a function at all.
  5. Every gate is a rule that turns input voltages into an output voltage.
  6. Every value in the whole machine is a pattern of those voltages, read as a number by whatever chooses to read it — which is where Week 1 started.

Six rungs, from a memory cell to a voltage, with nothing skipped and nothing taken on faith. If any of them is a sentence you can recite but not explain, that is the part to re-read before you sit the quiz.
