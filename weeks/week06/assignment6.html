Part A — Logisim Checkpoint 2a (50 points)

Build the seven ALU operation legs, the 8-bit comparator and the zero function. Each one is built and tested on its own. There is no ALU assembly in this checkpoint — no decoder, no output-selection stage. That is Checkpoint 2b next week.

Two things that catch people, both worth checking before you submit

The comparator's seeding. Bit 7's instance takes pl = 0 and pe = 1 from Wiring constants. The XOR_CMP_8BIT test value above is chosen specifically to fail if you seeded them the other way round, or if you left the pe term out of the l expression. If al comes out 0 for that row, one of those two is why.

A freshly built circuit may show E. If any of your circuits contains a MEM_1BIT that has never been written — which can happen if you build the shift legs out of registers — Logisim shows E on its output and a red wire until the first time it is set. This is correct behaviour and not a fault in your circuit. Toggle s from 0 to 1 once and it clears permanently.

Part B — Written (12 points, 3 each)

A few sentences each. I am looking for the reasoning, not the length.

1. (3 points) The ALU performs all seven operations on every input and discards six of the results. Give one reason this is a sensible design rather than a wasteful one.

2. (3 points) Opcode 111 is not connected to anything. Describe what appears on the ALU's 8-bit output when 111 is selected, and explain why that is different from the output being 00000000.

3. (3 points) The machine has no subtract leg. Explain how it computes A − B using only components you built this week, and name the Week 1 idea that makes it work.

4. (3 points) 10101010 shifted right by one, with shin = 0, gives 01010101. Explain why this is division by two if the byte is read as unsigned, and why it is not if the same byte is read as signed. Use the actual values in your answer.

Part C — From instruction to hardware (18 points, 3 each)

For each instruction: name the ALU leg or legs the course machine uses, and give the 8-bit result that ends up in the destination register. Two of the six do not work the way the other four do — that is the point of the exercise, so read each one rather than pattern-matching.

Throughout: $t1 = 11001010 and $t2 = 10110110.

1. (3 points) add $t0, $t1, $t2

2. (3 points) sub $t0, $t1, $t2

3. (3 points) and $t0, $t1, $t2

4. (3 points) nor $t0, $t1, $t2

5. (3 points) slt $t0, $t1, $t2 — and say which ALU output the answer comes from, not just what the answer is.

6. (3 points) andi $t0, $t1, 0x0F — and state whether the immediate is sign-extended or zero-extended, and why.

Part D — A MARS program (20 points)

Write a complete MIPS program, test it in MARS, and submit it as lastname_firstname_week6.asm. This is a separate file upload — do not paste it into the PDF.

Starting data

.data p: .word 420 q: .word 185 r: .word 97

What the program must compute

  1. $s0 = (p + q) − r
  2. $s1 = the low byte of $s0, using an immediate instruction
  3. $s2 = $s0 with bits 8–11 set, using an immediate instruction
  4. $s3 = the bitwise NOT of $s1. MIPS has no NOT instruction — use nor and $zero
  5. $s4 = 1 if $s1 < $s2, else 0, using slt
  6. $s5 = 1 if $s1 < 200, else 0, using slti
  7. $s6 = $s1 AND $s2, register form
  8. $s7 = $s1 OR $s2, register form
  9. $t0 = $s1 + (−52), using addi
  10. Print $s0 as an integer, then exit cleanly
Program requirements
  • .data first, then .text. No main: label and no .globl main. Execution starts at the first instruction in .text.
  • All ten Week 6 instructions used at least once: add sub and or nor slt addi andi ori slti.
  • A comment header with your name and a one-line description.
  • A comment on every instruction saying what it does — not what it is called.
  • No multiply, divide, shift or lui instructions. Everything on the list above can be done without them.

That is not a mistake. nor inverted every bit of a small positive value, which turns the leading zeros into leading ones, and a leading 1 in two's complement reads as negative. The bits are exactly right; MARS is showing you a signed reading of something that was never meant to be a signed number. If your $s3 is 0xFFFFFF03, you are correct.
