Converting Between Bases

Estimated time: ~1.5 hours  |  Sections: 1.4–1.5  |  Prerequisite: SPA 1 (Why Binary?)

What We Have / What We Can't Do / What We Can Now Do

What you already know: You understand the physical constraint (two voltage states), the vocabulary (bit, byte, word), and the three number systems (binary, hex, octal) from SPA 1.

What you can't do yet: Take an arbitrary decimal number like 317 and convert it to binary. Or look at a hex value like 0xA3F and quickly determine its binary representation.

What you will be able to do by the end of this SPA: Convert fluently between decimal, binary, hexadecimal, and octal using mechanical techniques. Understand the range of unsigned integers and what happens when you exceed it (overflow).

In SPA 1 you learned what binary, hex, and octal look like. Now you need to learn how to convert between them—a mechanical skill that becomes automatic with practice. These are not optional skills. You will use them every week of this course, from reading memory dumps in MARS to tracing signal values in Logisim.

1.4 — Converting Between Bases

Decimal → Binary (Repeated Division)

Divide the decimal number by 2 repeatedly, recording the remainders. Read the remainders bottom to top (last remainder is the most significant bit).

Example: Convert 66 to binary

66 ÷ 2 = 33  remainder 0
33 ÷ 2 = 16  remainder 1
16 ÷ 2 =  8  remainder 0
 8 ÷ 2 =  4  remainder 0
 4 ÷ 2 =  2  remainder 0
 2 ÷ 2 =  1  remainder 0
 1 ÷ 2 =  0  remainder 1
Read bottom-to-top: 1000010 → pad to 8 bits: 01000010

Binary → Decimal (Sum of Powers)

Add up the powers of 2 for each position that has a 1.

Example: 01000010

= 0×128 + 1×64 + 0×32 + 0×16 + 0×8 + 0×4 + 1×2 + 0×1
= 64 + 2
= 66

Binary ↔ Hex (Grouping by 4)

Group the binary bits into sets of 4 (from right to left), then look up each group in the hex-to-binary table from SPA 1.

Example: 01000010 → 0100 0010 → 4 2 → 0x42

Decimal → Hex (Divide by 16)

Same as decimal → binary, but divide by 16.

Example: 66 → hex

66 ÷ 16 = 4  remainder 2
 4 ÷ 16 = 0  remainder 4
Read bottom-to-top: 42 → 0x42

1.5 — Unsigned Integer Representation

An unsigned integer is the simplest form of data: a non-negative whole number stored as a binary value. The number of bits determines the range:

Bits Minimum Maximum Range Size
4 0 15 2&sup4; = 16 values
8 0 255 2&sup8; = 256 values
16 0 65,535 2¹6; = 65,536 values
32 0 4,294,967,295 2³2; values

The maximum value for n bits is 2n − 1 (all 1s). This formula appears repeatedly.

What happens at the boundaries?

If you add 1 to the maximum value (e.g., 255 + 1 in 8 bits), the result wraps around to 0. This is called overflow, and it is not an error — it is the natural behavior of fixed-width binary arithmetic. The CPU has an overflow flag it sets when this happens, but the bits still represent a valid (wrapped) value.

Key Takeaway

Overflow is not a crash. It is a predictable consequence of fixed-width representation. The hardware sets a flag and keeps running. It is up to the program (or the programmer, in assembly) to check the flag and handle the condition.
