14.13   One test per class, with the answer written first

A test is only a test if you know the answer before you run it. Each program below exercises one class of instruction, is short enough to trace by hand, and ends in a state that would be wrong if any one step of that class were wrong. These are Checkpoint 7’s three tests. Trace each one before you load it.

Test A — memory and immediates

AddrBytesInstruction

Two DATAs put an address (0x1E) in R0 and a value (0x5A) in R1. ST R0, R1 writes 0x5A to address 0x1E, which the program never otherwise touches. LD R0, R2 reads it back into R2. If R2 ends as 0x5A, the value went out to RAM and came back: both transfers, both MAR writes. Expect: R0 1E · R1 5A · R2 5A · RAM[1E] 5A · PC 06.

Test B — jumps

AddrBytesInstruction

The program is built so that every wrong path ends early with a register you can see. If JMPR R3 fails, the CPU runs DATA R0, 0xAA and stops at 0x05 with R0 = AA. If JMP 0x0B fails, it runs DATA R0, 0xBB. Only a CPU whose two jumps both work reaches 0x0B, loads R1 = 01 and stops at 0x0D with R0 still 00. Expect: R0 00 · R1 01 · R3 07 · PC 0D.

Test C — flags, conditional jumps and the carry-in

AddrBytesInstruction

0xFF + 0x01 = 0x100: R1 becomes 00 and C becomes 1, so JC 0x0A must jump, over DATA R2, 0xEE. At 0x0A, ADD R2, R3 adds 0 + 0 — plus the carry CTMP copied at step 4 — so R3 = 01 proves the carry-in path. That addition has no carry out and a non-zero result, so JZ 0x0F must not jump, and DATA R2, 0x22 runs. Expect: R0 FF · R1 00 · R2 22 · R3 01 · C A E Z = 0 0 1 0 · PC 0F.

Read the failures as well as the passes. R2 = EE means JC fell through; R3 = 00 means no carry-in; R2 = 00 means JZ jumped when it should not have.

14.14   From MIPS to your CPU

In Week 7 you wrote loops in MIPS. Here is one that adds 5 + 4 + 3 + 2 + 1:

addi $t0, $zero, 5 # n addi $t1, $zero, 0 # sum loop: add $t1, $t1, $t0 # sum = sum + n addi $t0, $t0, -1 # n = n - 1 bne $t0, $zero, loop # until n is 0

Translating it shows each difference between the two instruction sets:

  • No immediate add. addi $t0, $t0, -1 becomes a register holding −1 — 0xFF in two’s complement, loaded once with DATA R3, 0xFF — and an ADD.
  • Two operands, not three. ADD RA, RB writes RB. add $t1, $t1, $t0 becomes ADD R0, R1 (R1 = R0 + R1); the decrement becomes ADD R3, R0 (R0 = R3 + R0).
  • The carry comes back. Adding 0xFF carries out every time but the last, and the next ADD would add that 1. A CLF before each ADD keeps the arithmetic clean.
  • No bne. Jcaez jumps when a flag is 1, and Z = 1 means “zero”. So “branch if not zero” becomes “jump out if zero” followed by an unconditional jump back.
  • Absolute addresses. bne’s target is an offset from the PC; JZ and JMP carry the address itself, so you count bytes — remembering that DATA, JMP and Jcaez are two bytes each.
AddrBytesInstruction

R1 ends as 0x0F, which is 15. Load it into the Test Bench below and look at the trace: the loop body runs five times, and the fifth ADD R3, R0 makes R0 zero, so JZ leaves.

14.15   MYSIM.txt: multiplying with shifts and adds

Your CPU has no multiply instruction. MYSIM.txt multiplies 5 × 5 the way you multiply by hand, one digit of the multiplier at a time — except that in binary each digit is 0 or 1, so each partial product is either the multiplicand or nothing:

AddrBytesInstruction
  • R0 is the multiplier. SHR R0, R0 pushes its lowest bit out into C, and JC 0x0D adds only when that bit was 1.
  • R1 is the multiplicand. SHL R1, R1 doubles it each time round: the next column’s partial product.
  • R2 is the running total: ADD R1, R2, R2 = R1 + R2. It must start at 0, which XOR R2, R2 does — if R2 holds a value. That is why the procedure presses RESET.
  • R3 is the counter: a 1 that SHL R3, R3 walks left. After eight shifts it falls out into C, and JC 0x16 reaches END.
  • Three CLFs, because every shift and ADD takes CTMP’s carry in. There is no CLF before SHL R3, R3, so when SHL R1, R1 carries out, that 1 enters R3 at the bottom. It never reaches the top in time to matter, but it is why R3 ends as 00000101, not 0.

The run takes 77 instructions; R2 ends as 00011001, 25.

Which register is which

In the video your instructor says he is not sure which of R0 and R1 is which, and talks through shifting R0 left and R1 right. In MYSIM.txt it is the other way round: R0 shifts right (the multiplier, read one bit at a time) and R1 shifts left (the multiplicand). With 5 × 5 the answer is the same either way.
