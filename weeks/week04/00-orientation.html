Week 4 — The Week Logic Becomes Memory

Sequential Logic & 1-Bit Memory  |  09/07 – 09/13  |  Estimated time: ~8 hours

Where you are, and what is missing

What you built last week: circuits that do real work. An 8-bit adder that adds two whole bytes. Decoders at three widths that turn a binary code into a one-of-N selection. Real components, built to spec, that go into the CPU you finish this course with.

What you can't do yet: remember any of it. Every circuit you have built is combinational — its output depends only on what its inputs are right now. Change the inputs and the previous answer is not stored somewhere; it is simply gone.

That rules out more than it first appears. You cannot add three numbers, because there is nowhere to keep the first sum while you fetch the third. You cannot count. You cannot do one thing and then another, because "and then" requires remembering that the first thing happened. Without memory there are no programs — only a fixed shape that transforms whatever is presented to it.

What you will be able to do by the end of this week: store a single bit that persists until you deliberately change it — built from two NAND gates wired back into each other. No new component, no special memory ingredient. Then control when it is allowed to change, and build the memory cell that every register in your CPU is made of.

This is the pivot

The week the machine gets a past

Every week so far has added a capability. This week changes what kind of machine you are building.

Before this week, a circuit was a shape that transformed whatever was presented to it. After this week, a circuit can have a past. Registers, RAM, the program counter, and the entire idea of a machine that does one instruction and then the next all rest on the two gates you wire together in this module.

Week 2 proved that NAND can build any logic function. This week collects on that a second time, in a way the universality proof did not predict: two NAND gates can build something that is not a logic function at all. A logic function's output is determined by its inputs. This circuit's output is not — and that is exactly what makes it memory.

What you build, and where it goes

  • SR_LATCH Two cross-coupled NAND gates. The mechanism, in its rawest form — and the one circuit this semester that you build to understand rather than to use.
  • MEM_1BIT Four NAND gates. Your CPU's memory cell. Week 5 places eight of them side by side to make a register, and every register, the program counter, the memory address register and every byte of RAM in your finished machine is made of these.

Two circuits is the smallest number any week has asked for, and it is deliberate. This week is short — see below — and the hours it has belong to understanding the first one properly rather than to building a third.

No new install this week

One file, all semester

Every circuit you build in this course lives in one .circ file as a separate tab. Not a file per week, not a "master" file that links to others — one file. A submission that references circuits living in other files opens as a broken circuit on the grading machine and is marked incomplete.

Which components you may use — and the shortcut that appears this week

You may freely use anything from Logisim's Wiring folder (input and output pins, splitters, tunnels, constants, probes) and anything from Gates (NAND, AND, OR, NOT, NOR, XOR, XNOR, and the buffers).

Do not use anything from Plexers, Arithmetic, or Memory.

That last one matters this week for the first time. Logisim's Memory folder contains a D Flip-Flop, an S-R Flip-Flop and a Register — components that would do this week's work for you in about ten seconds. Using one produces a circuit that functions and teaches nothing, and every checkpoint from Week 5 onward instantiates your MEM_1BIT. Build it yourself.
