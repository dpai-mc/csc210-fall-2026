What the agent does

Every California community college course has a Course Outline of Record (COR), the official document that lists what the course must teach and the student learning outcomes (SLOs) students must show. The agent opens every live page of a course, reads it, and reports:

  • which COR topics and outcomes each page covers, and how deeply,
  • whether every learning outcome is actually graded, ideally once early and once late in the term,
  • problems it notices on pages (a points table that doesn't add up, a broken link),
  • a draft grading spreadsheet for each assignment, with short answer-key notes.

It was tested on three real courses: CSC141 (this one), CSC210 Computer Architecture, and its lab, CSC210L.

Who did what: two AIs and one human

Two different AI systems are involved, and they do different jobs. Mixing them up is one of the most common misunderstandings about "AI agents."

🧑‍🏫

The instructor

The decision maker and final checker

Set the goals and the rules ("the student pages are the truth", "no student work ever goes to an outside AI"), ran the agent on his own PC, and checked its output against the real course pages.

💬

A frontier AI coding assistant

Helped build the agent (Claude)

Read the course folders (read-only), proposed designs, asked clarifying questions, wrote and tested the Python code, and reviewed run logs and outputs with the instructor.

🖥️

A local AI model

Runs inside the agent (Qwen, 27 billion parameters)

Runs on two graphics cards in the instructor's own computer, so nothing leaves the building. It does the reading and judgment: "Does this page teach COR topic 4? At what level?"

Lessons that apply to any AI project

★ The biggest simplification: ask for a grid, not an essay

The biggest improvement didn't come from better code or a bigger model. It came from changing the shape of the output. The first compliance report was well-written prose that took a long time to check. The new one is a matrix: pages down the side, COR items across the top, and a 1, 2, 3 or blank in each cell.

That helped both sides. The model answers a small, concrete question about one page ("which topics, at what level?"), which it does far more reliably than judging a whole course. The human can check the result in minutes: a blank column is a gap, and a column that never gets past 1 is only ever introduced.

1. Look before you build

The first plan was wrong. Reading the real course folders before writing code showed that a different design was needed. An hour of looking saved days of rework.

2. Ask, don't assume

Eleven questions to the instructor settled things no AI could guess, like "is the syllabus or the web page the truth?" Those answers are now rules the agent follows.

3. Use plain code where you can

Adding up points, finding links and following a weighting formula are jobs for ordinary code, which gets them exactly right every time. The AI handles the parts that need judgment.

4. Check against a known answer

The instructor had a grading sheet he'd built by hand. When the agent built the same sheet exactly, that was real evidence it worked. "It looks plausible" is not evidence.

5. Don't over-fit the instructions

It's tempting to add a rule every time the AI makes a mistake. A rule written to fix one page was removed again, because a pile of rules like that makes the agent worse on everything else.

6. Know when to stop

The compliance report works well. The grading keys for one course still have problems. Pausing to do other productive work is a legitimate exit from the loop, as long as the limits are written down.

Where it still struggles

An honest list. Every item was found in the Validate step by a human comparing the agent's work with the real course pages.

ProblemExampleWhy it matters
Confident technical errors in answer keysFor a lab circuit, the key used NAND gates where the page's own hints require NOR gates. In another key, one binary result was off by a single bit.A wrong key grades students wrong. Every key needs an expert's review before use.
"Thinking" that runs too longOn the hardest assignments, the model spent its whole output budget reasoning and never wrote an answer. One six-hour run ended with the PC locking up.Reasoning models can loop. The fix was to log everything, save the cut-off answer, and retry without thinking.
False findingsAbout 25 "problems" on one course were not real. The agent was reading the raw file rather than the page a student sees after its scripts run.Garbage in, garbage out: the input has to match what students really see.
Run-to-run variationRunning the same page twice can produce slightly different observations.Treat AI findings as leads to check, not as verdicts.

Discussion questions

  1. The agent uses a local model for anything near student data, and allows a frontier (cloud) model only for course content. What risks does that rule protect against? What does it cost?
  2. The answer key with the NAND/NOR error looked completely professional. How would you design a check that catches errors like that without an expert re-doing all the work?
  3. Lesson 5 says not to add a rule for every mistake. When is it right to add a rule? Where would you draw the line?
  4. Which parts of this loop could an AI do by itself? Which parts should always stay with a person? Why?
  5. Think of something you've built, written or fixed. Where did your own build → run → validate → repeat loop show up, and where did you skip the "validate" step?

Glossary

Agent
A program that uses an AI model as one part of a larger process: it gathers information, asks the model for judgments, checks the answers, and produces results with little hand-holding.
Local model
An AI model that runs on your own hardware. Nothing is sent over the internet.
Frontier model
The most capable models from companies like Anthropic, OpenAI and Google. They run in the provider's cloud.
Token
A chunk of text, roughly ¾ of a word, that a model reads or writes. Output is limited by a token "budget."
Thinking mode
A setting where the model writes out hidden reasoning before its answer. Often better results, but slower, and it can run out of budget.
Deterministic
Gives the same output every time for the same input. Ordinary code is deterministic; AI models usually are not.
Validation
Checking output against something you trust: the source page, a hand-built example, or an expert.
COR / SLO
Course Outline of Record / Student Learning Outcome: the official description of a course and the skills students must demonstrate.
