2.3 — NAND and NOR: The Universal Gates

A Reminder, Then the Point

You met NAND and NOR on the last page. As a refresher:

ABA NAND BA NOR B
0011
0110
1010
1100

NAND outputs 0 only when all inputs are 1. NOR outputs 1 only when all inputs are 0. Nothing new so far — they are AND and OR with a bubble.

This page is not about what these gates do. It is about a property they have that the other five do not.

The critical insight

The NAND gate is universal. You can build any logic function — no matter how complex — using nothing but NAND gates.

You can build AND from NAND. You can build OR from NAND. You can build NOT from NAND. And since AND, OR, and NOT together can express any logic function at all, NAND alone can build any circuit that has ever been built or ever will be.

The Three Derivations

Here is how each one works. Build these in the widget below before you read further — the point lands better when you have toggled the inputs yourself.

NOT from NAND. Tie both inputs of a single NAND gate together. A NAND outputs 0 only when both inputs are 1; with the inputs tied, that means it outputs 0 exactly when the input is 1, and 1 exactly when the input is 0. That is inversion.

  • NAND(0, 0) = 1   →   NOT 0 = 1
  • NAND(1, 1) = 0   →   NOT 1 = 0

AND from NAND. A NAND is an AND with the output inverted. So invert it back: feed the NAND's output into a second NAND wired as a NOT. Two gates total.

OR from NAND. Invert both inputs with NAND-as-NOT gates, then feed those into a third NAND. Three gates total.

Why does the OR derivation work?

The AND and NOT derivations are easy to see. The OR one is not obvious, and it should not feel obvious yet — it follows from De Morgan's laws, which are the subject of the next page.

Why This Mattered Enough to Build Computers Around

Early computer chips were manufactured almost entirely from NAND gates. Three reasons:

  1. Manufacturing simplicity. A chip factory only needs to produce one type of gate. Fewer variations means fewer process steps, fewer defects, and lower cost.
  2. Speed. NAND gates are cheaper to fabricate than AND gates, because an AND is physically built as a NAND followed by an inverter. The NAND is the primitive; the AND costs extra.
  3. It works. If one gate type can build any function, you never need a second one.

This is not a historical curiosity. The Intel 4004, the first commercial microprocessor, shipped in 1971 built largely from NAND logic. The Apple I used chips built the same way. The CPU in the machine you are reading this on uses a mix of gate types for efficiency — but it could have been built from NAND alone, and nothing would have changed about what it can compute.

NOR Is Also Universal

NAND is not special in this respect. NOR — whose table you saw at the top of this page — is universal for exactly the same reasons, and the derivations work the same way with the roles of AND and OR swapped.

Deriving AND, OR, and NOT from NOR is a good exercise, and you will do one case of it in Assignment 2.

Why this course emphasizes NAND over NOR

Both gates are universal, so the choice is partly arbitrary. Ours is not: in Week 4 you will build an S-R latch — the first circuit in this course that can remember a bit, and the foundation of all computer memory — from two cross-coupled NAND gates.

NAND universality is not an academic aside here. It is the thread that runs from this page to the end of the course.

What You Just Learned

Every circuit you will build in this course — the adder in Week 3, the S-R latch in Week 4, the register in Week 5, the ALU in Week 6, the RAM in Week 8, and the CPU you assemble across Weeks 13 and 14 and submit as your final project — can be built from nothing but NAND gates.

You have already seen the single most important fact about digital hardware. The rest of this course is applying it.

Forward reference

You now know that the derivations work, because you tested them. Next you will learn why they work. Boolean algebra — and specifically De Morgan's laws — turns the OR-from-NAND construction from a trick you verified into a result you can prove.

That same algebra is what lets you shrink a circuit before you build it: fewer gates, faster hardware. In Week 6 you will use it to cut gate count in the ALU's control logic.
