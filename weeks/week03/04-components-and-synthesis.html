Encoders, Comparators, and What You Now Own

3.7   Encoders and Comparators

Two more circuits round out the picture. Neither is on your assignment — both are here because you will meet them inside the ALU and the control unit, and because the second one demonstrates a technique you have already used without naming it.

The encoder

An encoder is the decoder run backwards.

A decoder takes a code and raises one of many lines. An encoder takes many lines, exactly one of which is high, and produces the n-bit code that names it. Sixteen input lines in, a 4-bit code out.

Where is that useful? Any time something out in the machine raises a line and the processor needs to know which line it was, as a number it can work with. A keyboard raising one line per key, and the encoder turning that into a key code, is the classic example.

What if two inputs are high at once?

A plain encoder has no answer — its output is meaningless, because it was built on the assumption that exactly one input is active.

The fix is a priority encoder, which is given a rule: when several inputs are high, report the highest-numbered one and ignore the rest. Real interrupt controllers work exactly this way — several devices can ask for attention simultaneously, and something has to decide who gets served first.

We are not building one. It is worth knowing the name and the reason it exists.

The comparator

A comparator takes two values and reports how they relate: whether they are equal, and which is larger.

Start at one bit, and it is small enough to reason through completely. Given inputs A and B, three questions:

QuestionWhen is it true?The gate
A equals B Both 0, or both 1 — the bits are the same XNOR, which is exactly "these agree"
A is greater than B A is 1 and B is 0 AND of A with B'
A is less than B A is 0 and B is 1 AND of A' with B

Three gates and two inverters, and the one-bit comparison is complete. Notice that XNOR — a gate you might have filed away as an oddity in Week 2 — turns out to be the natural expression of "equal." That is a recurring experience in this material: the gate you could not find a use for is the obvious answer to a question you had not asked yet.

This one is a worked example, not a deliverable

The 1-bit comparator is here to be understood, not submitted. It is not one of the six circuits in Assignment 3, and there are no points attached to it. Build it in Logisim if you want to see it work — it is five minutes — but nothing asks you to.

Making it wider — and a technique you have already used

Wider comparators are built the same way the adder is: identical stages chained together, each one passing status along to the next. One stage per bit, each handing the next stage what it has concluded so far.

You built a chain like this two pages ago. In the ripple-carry adder, what travelled along the chain was a carry. In a comparator, what travels is a verdict — equal so far, or already decided.

bit 7 (MSB) bit 0 (LSB)

The comparator's chain runs in the direction shown. The direction differs from the adder's, for a reason you will see when you build the ALU.

Chaining identical stages is the technique, not the circuit

This is the second time this week you have seen the same move: build one small stage, verify it completely, then chain copies of it and let information flow along the chain.

Seeing it twice, in two circuits that do entirely different jobs, is what makes it a technique rather than a quirk of adders. It appears again inside the ALU, and again in the datapath. When you meet a circuit that has to work on a whole word, this is almost always how it is built.

Nothing new went into the toolbox this week

Look back at what any of these circuits is actually made of. The adder is XOR, AND, and OR. The decoder is NOT and AND. Not one new primitive was introduced.

Everything you gained this week came from arrangement — from putting known parts together in a particular shape. That is the central fact of hardware design, and it does not stop being true at any level above this one. The CPU is gates. The computer is gates. It is arrangement all the way up.

3.9   Looking Ahead: Circuits That Forget

There is something every circuit you have built so far cannot do, and it is easy to miss because nothing has asked for it yet.

What we have

Circuits that perform arithmetic and selection on multi-bit values. Real components, built to spec.

What we can't do yet

Remember anything.

Every circuit built this week is combinational — its output depends only on what its inputs are right now. Change the inputs and the old answer is simply gone. There is nowhere for it to have been kept.

Think about what that rules out. You cannot add three numbers, because there is nowhere to put the first sum while you fetch the third. You cannot count. You cannot do one thing and then another thing, because "and then" requires remembering that the first thing happened. Without memory there are no programs — only a fixed shape that transforms whatever is presented to it.

It is the same fact from page 2 seen from the other side. A circuit does everything, all the time. That is enormously powerful and it is also the problem: a machine that is always doing everything cannot do one thing and then another. Sequence has to be built, and it has to be built out of something that can hold still.

What you will be able to do next week

Store a single bit that persists until you deliberately change it.

Built — and this is the part worth being surprised by — from two NAND gates wired back into each other. No new component, no special memory ingredient. Two of the gates you already have, with each one's output feeding the other's input.

That circuit is where logic becomes memory, and it is the most important single idea in this course. Everything after it — registers, RAM, the program counter, the whole notion of a machine that executes one instruction and then the next — rests on it.

And once something can hold a value, a second question follows immediately: when should it change? That is what the clock is for, and it arrives next week alongside the flip-flop. The clock is how a machine that does everything all the time is persuaded to take turns.

Week 2 proved NAND could build any logic function. Next week collects on that investment a second time, in a way the universality proof did not predict: two NAND gates can build something that is not a logic function at all.
