The Memory Bus

Sections 12.1 – 12.4  |  Estimated time: ~1 hour

12.1   What a memory needs to be told

What you have. A CPU core that runs ALU instructions under its own control unit, and, in a separate tab since Week 8, a RAM with its own memory address register. What you can’t do yet. Get a byte from the RAM into a register, or back. What you can do by the end of this page. Say exactly which transfers your CPU will use for LD and ST, and what the RAM sees during each.

Every memory, from your 32-byte RAM to the gigabytes in a laptop, has to be told three things on every access, and the wires that carry them are named for what they carry:

  • Address lines — which location. Eight of them reach 256 locations; 32 reach four billion.
  • Data lines — the value itself, going into memory on a write and coming out on a read.
  • Control lines — what to do and when: read or write, and a signal that says the address and data are ready now.

Together they are the memory bus. Some processors give each group its own wires, so an address and data can travel at the same moment. Others share wires and send the address first, then the data. Yours is the second kind, as you are about to see.

Now remember that your CPU has one bus. In Week 13 the RAM joins it like this: address, i and o all connect to the bus, sa becomes the control unit’s MAR_S, s becomes RAM_S and e becomes RAM_E. The same eight wires carry an address in one transfer and data in the next. That is why the RAM has a MAR: the address has to stay put after the bus moves on to carry the data.

12.3   LD and ST are two transfers

You met the two memory instructions in Week 10: LD RA, RB loads RB from the RAM address held in RA, and ST RA, RB stores RB at the address held in RA. Both start the same way: RA drives the bus and the MAR captures it, so the address is locked in. Then they differ only in direction. A load lets the RAM drive the bus and a register capture; a store lets a register drive the bus and the RAM capture. 12.4   The 256/32 gap, from the CPU’s side

In Week 8 you designed a RAM for 256 addresses and populated 32 of them, rows 0 and 1, because Logisim slows to a crawl with the whole matrix. From the CPU’s side that has a precise consequence. An address from 0x00 to 0x1F selects a byte. An address from 0x20 up decodes to a row that has no bytes in it: the row line goes high and nothing answers. So a load from an unpopulated address leaves the bus floating, and the register captures nothing anyone chose; a store to one stores nothing at all. Try LD R2, R1 and ST R2, R1 above, with R2 = 01000000.

Real systems face the same gap on a larger scale: a 64-bit processor can name far more addresses than any machine has memory. Week 16 picks this up with the memory hierarchy.
