7.4   Two instructions left over from last week

Before control flow, ten minutes to close Week 6. You built two shift legs and never met the instructions that use them.

InstructionMeaningYour leg
sll $rd, $rt, shamt$rd = $rt shifted left by shamt placesSHIFT_LEFT
srl $rd, $rt, shamt$rd = $rt shifted right by shamt placesSHIFT_RIGHT

Both are R-type, and both use a field you have seen in the instruction format and never had a use for: shamt, five bits, the shift amount. Five bits gives 0 to 31, which is exactly the range that makes sense for a 32-bit register.

They are also the fast way to multiply and divide by powers of two. sll $t1, $t0, 3 multiplies by 8. A compiler will emit that rather than a multiply without being asked, because a shift is one of the cheapest things a processor can do and a multiply is one of the most expensive.

MIPS shifts by shamt. Your ALU shifts by one.

sll $t1, $t0, 5 moves every bit five places in a single instruction. Look at the leg you built: SHIFT_LEFT has an 8-bit input, a shin pin and an 8-bit output. There is no shamt input on it, and there is nowhere to put one — the wiring moves each bit exactly one position and that distance is built into the wires.

Real MIPS hardware uses a barrel shifter: a circuit that can shift by any amount in one pass, built from layers of multiplexers. It is considerably larger than what you built, and this course does not build one.

So your machine could execute sll $t1, $t0, 5 only by applying its shift leg five times, under something that counts. That is a real limitation of this design, not a simplification you will undo later — and it is worth knowing which of the two you are looking at whenever a course says "we'll do the simple version."

7.5   The register that decides what happens next

Every program you have written so far runs straight down the page. There is a reason, and it is one register.

The program counter — the PC — holds the address of the instruction being executed. After each instruction the machine adds 4 to it, because every MIPS instruction is four bytes long, and fetches whatever is there next.

Straight-line execution is one line of behaviour

PC = PC + 4

That is the whole of it. A program with no control flow is a machine doing nothing but adding 4 to a register, over and over, and reading what it lands on.

So every control-flow instruction in this week is a different way of writing some other value into the PC. A branch conditionally writes PC + 4 + something. A jump writes an address. A return writes back whatever was saved. There is no separate "control" mechanism hiding somewhere — deciding, looping and calling are all one register being written to.

You will build the PC as actual hardware in Week 13. It is a register — the same REGISTER_8BIT you built in Week 5, in the same file, with an adder wired to it. Knowing that now makes the rest of this page concrete rather than magical: when a branch "goes somewhere," a circuit you have already built is being loaded with a number.

7.6   beq, bne, and counting in instructions

MIPS has two instructions that compare two registers and conditionally change the PC:

InstructionOpcodeBranches when
beq $rs, $rt, label000100$rs equals $rt
bne $rs, $rt, label000101$rs does not equal $rt

A label is a name you put in front of an instruction. The assembler works out what address that instruction ended up at, and replaces the label with a number. Which number is the interesting part.

The offset, and why it is not an address

A branch is I-type, so it has a 16-bit immediate field to carry its destination in. An address is 32 bits. Sixteen bits cannot hold one.

So a branch does not store where to go. It stores how far to move, relative to where it already is:

target = PC + 4 + (offset × 4)

Two details in that formula are worth being deliberate about.

Why PC + 4 and not PC

By the time the branch is acted on, the machine has already added 4 to the PC — that is the default behaviour from §7.5, and it happens whether or not the branch is taken. The offset is measured from where the machine was going to go, not from the branch itself. An offset of 0 therefore means "carry on normally."

Why × 4 — and it buys four times the reach for nothing

Every MIPS instruction is four bytes and sits at an address that is a multiple of four. So a byte offset between two instructions is always a multiple of four, which means its bottom two bits are always zero.

Storing two bits that can never be anything but zero would waste two of the sixteen. So the field counts instructions instead of bytes, and the hardware multiplies by 4 when it uses the value. Same field, same instruction, four times the distance, and nothing given up — because the bits that were dropped carried no information.

This is worth noticing as a piece of engineering rather than as a rule to memorise. It is the same move as the ALU's shared carry and shift pins: find something the representation is spending bits on that it does not need, and get the bits back.

The reach: ±32,767 instructions

The offset is a 16-bit two's-complement number, so it runs from −32,768 to +32,767 instructions. Negative offsets branch backwards, which is how a loop works.

In bytes that is roughly ±128 KB — but quote the instruction figure, not the byte figure. The instruction count is what the encoding actually holds; the byte count is derived from it, and it is easy to get wrong by a factor of four in either direction.

If a branch target is further away than that, the assembler cannot encode it, and you need a jump instead. That is §7.9.

7.7   blt does not exist

You have two conditional branches: equal, and not equal. Now write this:

if (a < b) { ... }

Equal and not-equal cannot express less than. And yet you will find blt in every MIPS reference, in the Fall 2025 course material, and in most textbooks, used exactly as though it were an instruction.

It is not an instruction. The assembler writes two instructions for you.
you write: blt $t0, $t1, target the machine slt $at, $t0, $t1 executes: bne $at, $zero, target

slt puts 1 in $at if $t0 is less than $t1, and 0 otherwise. Then bne branches if that result is not zero. Two real instructions, and between them they do what one made-up instruction appeared to.

This is called a pseudo-instruction — something the assembler accepts and expands before anything reaches the processor. It is not a trick or a shortcut; it is one of the main jobs an assembler does.

And now look at where the answer comes from

You met slt last week, and you did not implement it. You did not need to — it was already there.

One C comparison, two assembly instructions, one wire

slt is answered by AL — the "A is larger" output of the comparator leg. That is the circuit you built in Week 6 out of eight chained XOR_CMP_1BIT instances, and wired into ALU_8BIT on page 1 of this week, where it runs continuously regardless of which opcode is selected.

So:

if (a < b)  →  slt + bne  →  one bit coming out of an XOR cascade

That is the whole stack, in one example, and it is why the comparator was worth a whole page last week. A high-level conditional is not implemented by some separate comparison machinery. It is implemented by the thing you wired up on Tuesday.

Where $at came from. Week 5's register table lists $at as "reserved for the assembler" and did not say what for. This is what for: the assembler needs somewhere to put an intermediate result when it expands a pseudo-instruction into several real ones, and $at is the register set aside so that doing so never destroys anything of yours. Do not use $at in your own code — an expansion two lines later will overwrite it without warning.
