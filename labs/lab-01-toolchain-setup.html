Why This Lab Exists

What we have: Numbers as humans write them, and a lecture that claims a computer represents all of them using nothing but two voltage states.

What we can't do yet: See it. Right now that claim is something you were told. You have no way to hold a byte, change it, and watch its meaning change.

What we can do after today: Build a working circuit that takes eight bits of input and displays that same byte simultaneously in binary, hexadecimal, and decimal — and run a program on a simulated MIPS processor that prints the same value. Two tools, one byte, three ways of reading it.

There is also a practical reason this is Lab 1 and not Lab 2. Every circuit you build for the rest of this semester lives in a single Logisim file that you create today. Every MIPS program you write runs in MARS. If those tools are not working by the end of this session, everything downstream is blocked. So the first 90 minutes are spent making absolutely certain that they work — on your machine, at the correct version, with a file you can open next week and every week after.

Take this seriously even though it feels like housekeeping. The most common way a student falls behind in this course is not conceptual difficulty. It is a tool that never quite got installed correctly in Week 1.

What You Will Be Able to Do

By the end of this session you will be able to:

  1. Launch Logisim Classic 2.7.1 and confirm the version, and explain why this course does not use Logisim Evolution.
  2. Launch MARS and confirm your Java runtime is working.
  3. Create and organize the single .circ file that will hold every circuit you build this semester, using named circuit tabs.
  4. Use the five Logisim tools you need for the entire course: select, wire, add component, poke, and probe.
  5. Build a circuit that displays one byte in binary, hexadecimal, and unsigned decimal at the same time.
  6. Convert a byte between bases by hand and verify your answer against hardware rather than an answer key.
  7. Load, assemble, and run a MIPS program in MARS, and locate the Registers and Data Segment panes.

Part 1 — Install and Verify Logisim Classic 2.7.1

Logisim is a digital circuit simulator. It is the laboratory of this course: every hardware idea from logic gates through a complete CPU gets built and tested here. You will spend more time in Logisim than in any other tool this semester.

You must use Logisim Classic version 2.7.1. Not 3.x, not "Logisim Evolution," not whatever version a search engine offers first. The next section explains why this is not an arbitrary preference.

1
Download from the course SharePoint

Both the Windows and macOS builds are posted on the course SharePoint site. Download the one matching your operating system. Do not download Logisim from anywhere else — other sources will hand you Evolution or a modified build.

2
Launch it

Windows: run the downloaded .exe.
macOS: the first launch will likely be blocked because the app is unsigned. Right-click (or Control-click) the app icon and choose Open, then confirm. Double-clicking will not work the first time; this is normal and is not a sign of a bad download.

3
Verify the version — this is graded

Open Help → About. The dialog must read 2.7.1. Take a screenshot of this dialog now; you will submit it.

If it reads anything else — especially if the window title says "Logisim-evolution" — you have the wrong program. Delete it and download again from SharePoint.

Checkpoint

Logisim opens to an empty canvas with a component tree on the left, and Help → About shows 2.7.1. You have a screenshot of that dialog.

Troubleshooting — Logisim won't start

Part 2 — Why Not Logisim Evolution?

Logisim Evolution is a newer, actively maintained fork. It is a good program. It is also the wrong program for this course, for one specific reason that matters enormously to how you will learn.

In this course you will build roughly forty circuits, and nearly every one of them will be reused as a component inside a larger circuit. A flip-flop becomes part of a register. A register becomes part of a register file. A register file becomes part of a CPU. By Week 14 you will be looking at a diagram containing a dozen subcircuits at once, and you will need to understand what you are looking at.

  Logisim Classic 2.7.1 (this course) Logisim Evolution
How a subcircuit is drawn Its actual gate-level shape A plain labeled rectangle
Reading a complex circuit You can see the structure at a glance You must read every label to know what anything is
What that means for you The picture teaches you The picture is a block diagram you have to decode

Visual circuit comprehension — looking at a circuit and understanding what it does without reading a description — is a learning outcome of this course, not a convenience. Evolution's rectangles quietly remove that outcome. That is why the constraint exists.

The Rule Behind the Rule

You will meet several constraints like this one during the semester: build everything from primitive gates, never use the built-in Adder or RAM components, use decoders rather than multiplexers for control. Each looks like an arbitrary restriction and each exists for the same underlying reason — nothing in this course is allowed to be magic. If a component appears in your circuit, you built it, and you can explain every wire inside it.

Part 3 — Install MARS and Verify Java

MARS (MIPS Assembly and Runtime Simulator) is where you will write assembly language starting in Week 5. It shows you the processor's registers and memory while your program runs, one instruction at a time. Where Logisim shows you the hardware, MARS shows you the same machine from the programmer's side.

You are installing it today, five weeks before you need it, for one reason: if your Java runtime is broken you want to discover that now, in a room with an instructor, rather than the night before your first MIPS assignment is due.

4
Download and launch MARS

Download Mars.jar from the course SharePoint. It is a single Java archive — there is no installer. Double-click it to run.

On macOS, the same unsigned-app block applies: right-click → Open the first time.

5
If MARS will not open, check Java

Open a terminal (macOS: Terminal; Windows: Command Prompt or PowerShell) and run:

java -version

If you see a version number, Java is installed and the problem is elsewhere — ask the instructor. If you see "command not found" or "not recognized," install a current Java runtime, then try again. Any recent Java 8 or later release will run both Logisim 2.7.1 and MARS.

6
Run the smoke-test program

In MARS, choose File → New, then copy this program into the editor pane exactly as written:

# CSC210L Lab 1 — MARS smoke test
# Prints a message, then prints the value 66.

        .data
msg:    .asciiz "MARS is running. Your value is: "

        .text
        .globl main
main:
        li   $v0, 4          # syscall 4 = print string
        la   $a0, msg
        syscall

        li   $t0, 66         # 66 = 0x42 = 0100 0010
        li   $v0, 1          # syscall 1 = print integer
        move $a0, $t0
        syscall

        li   $v0, 10         # syscall 10 = exit
        syscall

Save it as lab01_smoketest.asm. Then assemble it (Run → Assemble, or the wrench-and-screwdriver toolbar button) and run it (Run → Go, or the green play button).

7
Find the two panes that matter

You are not learning MIPS today. You are learning where to look. Locate these two and nothing else:

  • Registers pane (right side) — every MIPS register and its current value. After running, $t0 holds 66. Switch its display to hexadecimal and it reads 0x00000042. Same value, different base — exactly what you are about to build in Logisim.
  • Data Segment pane (bottom) — memory, address by address. Your string msg lives here. You will spend a lot of time in this pane in Week 8.
Checkpoint

The Run I/O pane at the bottom of MARS reads:

MARS is running. Your value is: 66

You can point to the Registers pane and the Data Segment pane. Take a screenshot showing the program assembled and this output; you will submit it.

Troubleshooting — MARS errors
"Error in line N: ..." when I assemble
Almost always a copy-paste problem. Check for a missing colon after msg, a smart quote (“) instead of a straight quote (") around the string, or a missing .text directive. Retype the offending line by hand.
It assembles but nothing prints
You assembled but did not run. Assemble and Run are two separate actions in MARS.
The .jar opens in an archive utility instead of running
Your OS has associated .jar files with a zip tool. Run it from a terminal instead: java -jar Mars.jar

Part 4 — Create Your Semester .circ File

This is the single most important five minutes of the lab, and the part students most often get wrong — usually in Week 12, when it is expensive to fix.

The Rule

Every circuit you build in CSC210 lives in one .circ file for the entire semester. Not one file per week. Not one file per circuit with a master file linking them together. One file, which grows a new circuit tab each week, from today through the final project.

Here is why this matters more than it sounds. Logisim lets a circuit reference a subcircuit stored in a different file. If you build each week's work in a new file and link them together, your master file opens beautifully on your own machine — because all the linked files are sitting right there in your folder. When you submit only the master file, it arrives on the instructor's machine with every one of those references broken. What renders is an empty shell.

This happens every single semester, and it is graded as incomplete, because a circuit that does not function when opened in isolation has not been demonstrated to work. Starting the habit correctly today costs you five minutes. Repairing it in Week 12 costs an evening.

8
Create the file with the required name

In Logisim: File → Save As. Name it using your own last name:

Pai_CSC210.circ

Save it somewhere you will not lose it — a dedicated CSC210 folder, not your Downloads folder. If you use cloud storage that syncs (OneDrive, iCloud Drive, Google Drive), that is a good choice: it gives you version history if something goes wrong.

9
Rename the default circuit tab

A new Logisim file contains one circuit, named main. In the Explorer pane on the left, right-click main and choose Rename (or select it and use the Project menu's rename option). Name it:

01-ByteReader

Use this naming convention all semester: a two-digit number for the order you built it, then a descriptive name with no spaces. By Week 14 your Explorer pane will read like a table of contents — 01-ByteReader, 04-SRLatch, 05-Register8, 06-ALU8, and so on. Circuits sorted alphabetically also sort chronologically, which is exactly what you want when hunting for the flip-flop you built two months ago.

10
Save, close, and reopen

Save the file. Then close Logisim completely and open the file again from your folder. Confirm the tab is still named 01-ByteReader.

This sounds pointlessly cautious. It is the cheapest possible test that your file is real, saved where you think it is, and not sitting unsaved in a temp directory.

Checkpoint

LastName_CSC210.circ exists in a folder you can find, contains a circuit named 01-ByteReader, and survives being closed and reopened.

Part 5 — Logisim Orientation: Five Tools

Logisim's toolbar has more buttons than you need. For the entire semester you will use five things constantly and the rest rarely. Learn these five now and the interface stops being an obstacle.

Tool What it does When you reach for it
Select (arrow) Selects, moves, and deletes components Rearranging a circuit; deleting a mistake
Wire Drags a wire between two points Constantly. This is most of circuit building.
Poke (hand) Changes an input's value while the circuit runs Testing. This is how you verify anything.
Pin (Wiring library) An input or output connection point Every circuit needs inputs and outputs
Probe (Wiring library) Displays the value on a wire, in a base you choose Debugging. Your most useful tool all semester.

Two conventions to absorb now, because they will save you hours later:

  • Green wire = value 0. Bright green = value 1. Red = error. A red wire almost always means two outputs are fighting over the same wire, or a bit-width mismatch. When something red appears, stop and find it — do not build on top of it.
  • Blue/grey wire = unknown value. Usually an input that isn't connected to anything yet.
A Habit Worth Starting Today

Probes are free and they cost nothing to leave in place. When your Week 13 CPU refuses to execute an instruction, the difference between a twenty-minute fix and a lost evening is whether you already had probes on the interesting wires. Place them liberally, starting now.

Part 6 — Your First Circuit: One Byte, Three Ways

Now build something. The circuit is deliberately tiny — three components and a few wires — because the point is not circuit complexity. The point is the idea underneath it.

A byte is eight bits. Those eight bits do not have a base. 01000010 is not "a binary number" that we then convert into decimal; it is a pattern of eight voltage levels, and binary, hexadecimal, and decimal are three different notations we use to talk about that pattern. Reading the same wire three ways at once makes that concrete in a way a conversion table cannot.

11
Place an 8-bit input pin

Open the Wiring library in the Explorer pane and select Pin. Before placing it, look at the attribute table in the lower-left corner and set:

  • Output? → No  (this makes it an input pin)
  • Data Bits → 8
  • Label → BYTE

Click on the canvas to place it. You should see a rectangle displaying eight bit positions.

12
Place three probes, each with a different radix

From the same Wiring library, select Probe. Place three of them to the right of your pin. Select each one in turn and set its Radix attribute:

  • Probe 1 → Radix Binary, Label BIN
  • Probe 2 → Radix Hexadecimal, Label HEX
  • Probe 3 → Radix Decimal (unsigned), Label DEC
13
Wire all three probes to the same pin

Using the Wire tool, drag from the output side of your BYTE pin to each probe. All three probes connect to the same wire — branch it rather than running three separate wires from the pin.

This is the whole idea made physical: one wire, one value, three readings. Nothing converts anything. The probes are just three different ways of printing the same eight voltages.

14
Poke it

Switch to the Poke tool (the hand) and click individual bit positions inside the BYTE pin to toggle them between 0 and 1. Watch all three probes update simultaneously.

Set the byte to 01000010. Your probes should read 01000010, 42, and 66. That is the same value MARS printed in Part 3 — and, if you interpret it as ASCII instead, the capital letter B.

Checkpoint

Poking any bit changes all three probe readings at once. Setting the byte to 01000010 gives you binary 01000010, hex 42, and decimal 66. Save your file.

The Point of This Circuit

The byte does not "know" it is 66. It does not know it is 0x42, and it does not know it is the letter B. It is eight voltages. Meaning comes from how something chooses to read it — a probe's radix setting, a MIPS instruction, a text editor, an image decoder. Change the reader, and the same bits mean something entirely different.

Hold onto this. In Week 11 you will build a circuit that reads a byte as an instruction and uses it to control the rest of a CPU. Same eight wires. Different reader.

Part 7 — Partner Conversion Drill

Pair up. You are going to convert bytes between bases by hand and check your answers against your circuit rather than against an answer key. This is a small thing that changes the exercise: an answer key tells you that you were wrong, while a circuit shows you what is actually true and lets you find your own error.

15
Take turns, six rounds each

Partner A names a value in one base — say, "hex 3F." Partner B writes the other two representations on paper without touching the computer. Then Partner B pokes the value into their Logisim circuit and both of you read the probes.

Swap roles and repeat. Six rounds each, mixing which base is the starting point.

16
When you disagree with the circuit, find out why

The interesting part is the errors. Two mistakes account for most of them:

  • Bit-position slips — getting 32 and 16 the wrong way round. The place values from left to right are 128, 64, 32, 16, 8, 4, 2, 1. Write them above your bits until you no longer need to.
  • Hex grouping errors — each hex digit is exactly four bits. Split the byte down the middle: 0100 0010 is 4 and 2, so 0x42. Never convert a byte to hex by going through decimal; group by four and read directly.

What Comes Next

Today you built a circuit with no logic in it. Eight bits went in, and the same eight bits came out and were displayed. Nothing was computed, nothing was decided, nothing was remembered.

That is the limitation Lab 2 attacks. Next week you build gates — circuits that take inputs and produce an output that is different from the input, according to a rule.
