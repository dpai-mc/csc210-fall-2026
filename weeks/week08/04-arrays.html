Arrays and Strings

Sections 8.12 – 8.15  |  Estimated time: ~1 hour

8.12   An array is a base address and some arithmetic

Week 1 said an array is its elements laid end to end in memory. Now you can see it. In C, int a[10]; reserves ten 4-byte integers, one after another — 40 contiguous bytes. The array has no other structure at all: no length stored anywhere, no boundaries between elements. There is a starting address, and there is arithmetic.

If the array starts at address base, then element i starts at

address of a[i] = base + 4 × i

That formula explains something you have probably taken on faith: C arrays start at index 0 because a[0] is the base address itself. The index is not a position in a list; it is a distance from the start, counted in elements.

An index is not a byte offset

a[3] is the fourth element, and it starts 12 bytes in, not 3. MIPS addresses count bytes; C indexes count elements. Every array bug on this page is a version of forgetting which of the two numbers you are holding.

In MARS you declare an array with .word (initial values) or .space (a number of bytes, all zero):

.data nums: .word 5, 12, -7, 20, 3, 9 # six ints: 24 bytes, at 0x10010000 len: .word 6 # the length is just another variable copy: .space 24 # room for six more, all zero

8.13   Walking an array

Visiting every element is a loop from Week 7 with a load in the middle. There are two standard ways to keep track of where you are, and both are worth knowing.

Index walk

Keep i in a register; turn it into an address every time round.

la $s0, nums lw $s1, len li $s2, 0 # sum li $t0, 0 # i loop: beq $t0, $s1, done sll $t1, $t0, 2 # i * 4 add $t1, $s0, $t1 # &nums[i] lw $t2, 0($t1) add $s2, $s2, $t2 addi $t0, $t0, 1 j loop done:

Pointer walk

Keep the address in a register; step it by 4.

la $t1, nums # p = &nums[0] lw $s1, len sll $t3, $s1, 2 add $t3, $t1, $t3 # end = &nums[len] li $s2, 0 # sum loop: beq $t1, $t3, done lw $t2, 0($t1) add $s2, $s2, $t2 addi $t1, $t1, 4 # p++ j loop done:

Both leave 42 in $s2. The index walk spends seven instructions per element; the pointer walk spends five, because it never has to turn an index into an address — the address is the loop variable. That is exactly why C programmers write *p++, and why a compiler often turns the first loop into the second for you.

Two details that matter:

  • sll $t1, $t0, 2 is the multiply by 4. Shifting left two places multiplies by 4 — Week 7’s sll, and nothing else needed. Your own ALU has no multiplier and shifts one place per pass, so on your machine this is two trips through the shift-left leg.
  • The loop bound is len, not 6. Load the length from memory rather than typing it into the branch. The array is data; the code should not have to change when the data does.
The Array Walker
Step either loop one instruction at a time and watch the address and the element move together.

8.14   Strings are byte arrays

A string is an array of characters, one byte each, holding the character codes from Week 1. MARS’s .asciiz directive lays one down and adds a zero byte at the end — the z in the name. That zero is the only thing marking where the string stops. There is no length stored; a program finds the end by walking until it reads a 0.

.data msg: .asciiz "hello, world" # 12 characters + 1 zero byte = 13 bytes .text la $t0, msg # p = &msg[0] li $t3, 'l' # the character to count: 108 li $s0, 0 # count loop: lbu $t1, 0($t0) # one character beq $t1, $zero, done # the terminator bne $t1, $t3, next addi $s0, $s0, 1 next: addi $t0, $t0, 1 # characters are 1 byte: step by 1, not 4 j loop done: # $s0 = 3

Two differences from the word loop, and each has a reason:

  • The pointer steps by 1. Each element is one byte, so the next one is one address on. The “multiply by element size” is still there — the size just happens to be 1.
  • lbu, not lb. For plain ASCII (codes 0–127) the two give the same answer, because the top bit is 0. But a byte from outside ASCII — an accented letter, or part of an emoji in UTF-8 — has its top bit set, and lb would sign-extend it into a negative number. A character code is never negative. lbu is the load that means “this byte is a value from 0 to 255”, which is what a character is.

li $t3, 'l' is MARS letting you write a character in quotes instead of looking up 108. It is the same number.

8.15   Both halves have memory

Phase 2 ends here. Look at what you now have on each side.

In hardware: a register, an ALU, and a RAM — storage for a value, a way to transform values, and a place to keep many of them, each reachable by a number. Every one is built from gates you placed and components you built earlier, in one file.

In software: programs that compute, decide, repeat, call procedures, and now keep data in memory and walk through it. That is every construct in a small C program, and you have seen what each one is at the level of the machine.

Four weeks ago these were two separate tracks. This week they met in a single instruction: lw $t0, 8($s0) is an add on your ALU, a latch in your MAR, a row and a column out of your decoders, and one AND gate in one byte of your RAM.

Phase 3 connects the parts. Week 9 steps back to the von Neumann model — the idea that a program’s instructions live in the same memory as its data, so the RAM you just built will one day hold the program too. Week 10 joins your ALU to a register file, and Week 12 connects memory to the CPU through a memory bus.
