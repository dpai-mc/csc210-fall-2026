Repeating and Jumping

Sections 7.8 – 7.9  |  Estimated time: ~1.4 hours

7.8   A loop is a branch pointing backwards

You have everything you need for a loop and may not have noticed. A branch offset is a two's-complement number, so it can be negative — and a negative offset sends the PC back to an instruction that has already run.

There is no loop instruction, and there does not need to be

An if and a while are the same machinery. The only difference is which direction the branch points: forward to skip over something, backward to do something again.

Every loop construct in every language you have used — while, for, do-while, foreach — compiles down to a label and a conditional branch. The variety exists for the programmer's benefit; the machine has one mechanism.

The three shapes

They differ only in where the test sits relative to the body.

While — test first, body may never run

loop: slt $at, $t0, $t1 # is counter < limit? beq $at, $zero, done # if not, leave # ... body ... addi $t0, $t0, 1 # advance j loop # unconditionally go back done:

Note the shape: the conditional branch exits the loop and the unconditional jump continues it. That reads backwards the first time you see it, and it is the standard arrangement — the test is written as "get out if finished" rather than "go round if not finished," which keeps the body in one straight run.

Do-while — test last, body always runs once

loop: # ... body ... addi $t0, $t0, 1 slt $at, $t0, $t1 bne $at, $zero, loop # go round again if still less

Shorter, and one instruction cheaper per iteration — no unconditional jump is needed, because the conditional branch is already at the bottom. This is the shape a compiler will produce when it can prove the body runs at least once.

For — a while loop with the bookkeeping gathered up

A for loop is not a separate mechanism at all. Its three parts — initialise, test, advance — are the same three pieces as the while loop, written in one line in the source and scattered in the same places in the assembly. There is nothing new to learn here, which is itself worth saying.

The 26-bit field, and why a jump is still not unlimited

A J-type instruction spends 6 bits on the opcode, leaving 26 for the destination. An address is 32 bits. Six are missing, and each one is missing for a different reason:

  • The bottom two are dropped for the same reason as in a branch — instructions are four-byte aligned, so those bits are always zero and carry no information. The field holds a word address.
  • The top four are not stored at all. At run time the machine takes them from the PC.

PC = ((PC + 4) & 0xF0000000) | (field << 2)

The << 2 is part of the formula, not a footnote

It is the step that turns the stored word address back into a byte address, and leaving it out is the most common way to get a hand-worked jump calculation wrong. The concatenation and the shift are one operation.

Borrowing the top four bits is what makes a jump a 256 MB jump

Twenty-six bits of word address is 2²⁶ instructions, which is 2²⁸ bytes — 256 MB. A jump can reach anywhere inside the 256 MB region it is already in, and cannot reach outside it at all.

Your programs will never notice, because everything you write sits in one region. But this is the reason jr exists as well: a register holds a full 32-bit address, so a jump through a register goes anywhere, at the cost of having to get the address into a register first.

jal and the return address

jal does two things in one instruction: it saves where to come back to, and then it goes. The saving is what makes a procedure call possible — a plain j into a procedure would arrive with no way of getting back.

jal fib # $ra ← address of the NEXT instruction; PC ← fib add $s1, $v0, $zero fib: # ... compute ... jr $ra # PC ← $ra — back to the add above
One caveat, stated once

On real MIPS hardware with delay slots, jal saves PC + 8. MARS runs with delayed branching turned off by default, so it saves PC + 4 — the address of the instruction immediately after the jal. That is what this course means throughout, and it is what the assignment expects.

Delay slots are a real feature of the architecture and a distraction here. If you turn delayed branching on in MARS, your programs will behave differently; don't.

Two instructions that exist and are not in this course

jalr jumps to an address in a register and saves a return address — what you would use for a jump table or a function pointer. bltz and bgez branch on the sign of a single register, and are encoded unusually: they share one opcode and are told apart by the rt field, which is the only place in MIPS where that field is not a register number.

Both are named here so that meeting them in a reference is not a surprise. Neither is taught, neither is on any assessment, and you do not need either one.

Where you are
